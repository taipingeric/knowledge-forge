# Use versioned atomic managed-state migrations

Knowledge Forge separately tracks State Schema Version, Workflow Version, and Generation Policy Version. Supported older state schemas are upgraded through deterministic, versioned migrations, while unsupported versions fail explicitly instead of being silently reinterpreted; workflow changes alone do not invalidate existing agent candidates, but generation-policy changes do. Existing PDF-only Bundles remain directly updateable and migrate to the generalized PDF source representation without wholesale Concept regeneration merely because orchestration changed. Managed validation remains read-only and reports when a supported migration is available; mutation commands migrate only in staging, combine migration with the requested operation, and publish both once so a later failure cannot leave a half-upgraded Bundle.
