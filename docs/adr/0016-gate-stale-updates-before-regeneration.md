# Gate stale updates before regeneration

When ordinary evidence or Generation Identity changes invalidate current agent knowledge, `update` leaves the live Bundle and managed state unchanged, writes `<out>.staleness.md` plus `<out>.staleness/manifest.json`, prints their location, and exits with code 4. The Regeneration Impact Report separates definitely stale Concepts whose referenced locator disappeared or changed, stale planning coverage caused by new or structurally changed evidence, and Agent-owned Concepts invalidated by generation changes; Imported and Human-owned Concepts are not marked stale merely because generation policy changed. Full planning and synthesis require explicit `--regenerate-all`, while affected-Concept incremental regeneration remains out of scope. After successful full regeneration, the pending `<out>.staleness/` machine workspace is removed and the Markdown report is rewritten as a resolved audit record. This operational signal does not modify OKF `status` or `stale_after`, because doing so would conflate dependency divergence with published lifecycle and freshness metadata and would violate atomic publication.
